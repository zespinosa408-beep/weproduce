# Color Visualizer

A paint color visualizer you can drop into a painting company's website. A visitor
picks a room or elevation, taps any surface, and tries colors on it — or uploads a
photo of their own house and paints that.

No build step, no dependencies, no framework. One stylesheet, one script, one `<div>`.

---

## Why it looks real

Most color visualizers overlay a translucent color on the photo. That is a
multiply: it washes out the shadows, it drags the old color through, and it can
only ever make a surface darker — so white over a navy house is impossible and
everything ends up looking like a sticker.

This one works from the model a photograph actually obeys:

```
observed  =  albedo (the paint)  ×  irradiance (the light landing on it)
```

Within one masked surface the albedo is a constant — it is one coat of one color —
so it can be estimated from the region's own statistics and **divided back out**.
What is left is the real light in the real photo: sun falloff, eave shadows,
ambient occlusion in the corners, the shadow under every lap-siding board, the
grain in a cabinet door. Multiply that by the new paint and the color lands *on*
the house instead of on top of it. Because a paint's albedo can be brighter or
darker than the old one, white-over-navy is no harder than navy-over-white.

Three details do the rest of the work:

| | |
|---|---|
| **Normalization** | The irradiance is scaled so the surface's well-lit part maps to exactly the color on the chip — the convention a customer judges against when holding a swatch up to the wall. Shade falls below it, glare rises above. |
| **Specular split** | Above a soft knee, brightness is treated as reflected highlight and added back as *white*, not as paint. Window glare and the sheen on a gloss door stay white instead of turning navy. |
| **Light cast** | Irradiance is recovered per channel, so the warm-sun / cool-skylight split in the original photo survives, blended toward neutral so the old hue can't contaminate the new one. |

All of it runs in linear light. Doing this math in gamma space is the single
biggest reason cheap visualizers look wrong.

### Measured behaviour

From `src/engine.js`'s model, verified against synthetic scenes with known ground truth:

- **Repainting a surface its own color returns the original photo** to within
  **5 levels out of 255** across the whole diffuse area — no visible jump between
  "original" and "the color it already is".
- **The lit area matches the chip** to ΔE ≤ 0.014 (OKLab).
- **Sheen changes contrast, not color**: flat → high gloss moves the lit:shade
  ratio from 4.08 to 6.36 while the lit-wall color stays put (ΔE ≤ 0.010).

## Install

Copy the `paint-visualizer/` folder to your site, then:

```html
<link rel="stylesheet" href="/paint-visualizer/dist/paint-visualizer.css">
<div id="visualizer"></div>
<script src="/paint-visualizer/dist/paint-visualizer.js"></script>
<script>
  PaintViz.mount('#visualizer', {
    brand: { name: 'Your Painting Company', accent: '#1f7a4d' },
    lead:  { endpoint: '/api/color-quote' }
  });
</script>
```

Or, with no JavaScript of your own — useful inside a page builder's HTML block:

```html
<div data-paint-visualizer
     data-config='{"brand":{"name":"Your Painting Company","accent":"#1f7a4d"}}'></div>
```

`dist/` is generated by `./build.sh`. During development, `index.html` loads
`src/*.js` directly so there is nothing to rebuild while editing.

### Options

| Option | Description |
|---|---|
| `brand` | `{ name, accent }`. `accent` drives the widget's UI color; `name` appears on downloaded images. |
| `lead` | `{ endpoint }` to POST selections as JSON, or `{ email }` to open the visitor's mail app. Omit both and the visitor gets a copyable summary. |
| `sceneFiles` | Array of URLs to scene `.json` files exported from the studio. |
| `scenes` | Scene descriptors, if you'd rather define them inline. |
| `includeDemos` | `false` to hide the two built-in demo scenes. **Set this once you have your own.** |
| `palette` | Your own palette object, same shape as `src/palette.js`. |
| `defaultScene` | Scene id to open first. |
| `studio` | `true` adds the scene-authoring buttons. |
| `updateUrl` | `false` to stop the widget writing selections into the URL hash. |

### The lead payload

With `lead: { endpoint }`, a submission POSTs JSON:

```json
{
  "name": "…", "email": "…", "phone": "…", "address": "…", "message": "…",
  "scene": "scene-m1abc",
  "link": "https://yoursite.com/visualizer#pv=…",
  "image": "data:image/jpeg;base64,…",
  "selections": [
    { "surface": "Siding", "color": "Dried Sage", "hex": "#a3b09a",
      "code": "PV-503", "sheen": "Satin" }
  ]
}
```

`image` is the rendered preview — handy to attach to the quote email. Pass
`lead: { endpoint, includeImage: false }` to leave it out and keep the request small.

## Adding your own photos

The demo scenes are drawn in code so the widget works with zero assets. **Replace
them with your own job photos** — that is where the realism comes from.

Open `studio.html`, click **+ Use my photo**, tap each paintable surface, name it,
and click **Export Scene**. You get one self-contained `.json` file with the photo
and every mask embedded. Drop it in `scenes/` and list it:

```js
PaintViz.mount('#visualizer', {
  sceneFiles: ['/paint-visualizer/scenes/smith-house.json'],
  includeDemos: false
});
```

**Name surfaces literally** — `Siding`, `Trim`, `Front Door`, `Shutters`,
`Garage Door`, `Upper Cabinets`, `Island`. The name sets the surface's role, which
is how one tap on a designer scheme applies a coordinated combination across the
whole house.

### What makes a good scene photo

Square-on, even light (overcast is ideal), the whole elevation in frame, nothing
parked in front. The engine *keeps* whatever shading is in the photo — so a clean
photo repaints cleanly, and a photo with a tree shadow across the siding will keep
that shadow in every color you try.

## Selecting surfaces

Tapping a surface runs a magic wand in OKLab with **luminance down-weighted**, so a
selection crosses a wall's full sun-to-shade gradient without stopping at the
shadow line. Straying onto the neighbouring trim is prevented separately, by an
edge map computed from the *unblurred* pixels — blurring first turns the hard step
at a trim board into a ramp a fill will happily walk across one small step at a time.

Measured on ground-truth masks: **99–100% recall at ~99% precision**, holding across
lap-siding texture and sensor noise.

### Where it struggles, and what to do

Two surfaces that are near the same color and meet with no hard edge — white upper
cabinets against a white wall — cannot be separated by color, at any sensitivity.
The widget detects this (a single selection covering more than 40% of the frame),
lowers the sensitivity automatically, and says so rather than handing back a
selection that has swallowed the room. From there, **Add** and **Remove** brush the
selection into shape.

This is why interiors are worth authoring in the studio, where you have time to
brush them properly, rather than leaning on the visitor to do it.

### Tuning the wand

`src/mask.js` exposes three tunables, fitted against ground-truth masks:

```js
PaintViz.mask.LUM_WEIGHT  = 0.32;  // how much shading is ignored
PaintViz.mask.EDGE_BASE   = 0.020; // weakest edge the fill refuses to cross
PaintViz.mask.EDGE_SLOPE  = 0.14;  // how far the slider loosens that
```

Tightening `EDGE_BASE` / `EDGE_SLOPE` to help interiors was tried and measurably
backfires: it cut exterior recall from 91% to 45%. Re-measure before changing them.

## About the palette

`src/palette.js` ships **90 original colors** with original names, in eight
collections, plus 11 designer schemes.

They are deliberately **not** any manufacturer's fan deck. Brand color names and
code numbers are trademarks, and the curated collections are themselves licensed
products — putting *"SW 7008 Alabaster"* on a public commercial site is a legal
question, not a technical one. Every entry has an empty `brand` field for mapping
your supplier's numbers in once you have the rights:

```js
{ name: 'Quarry Mist', hex: '#c9cbc6', code: 'PV-312', brand: 'XX 7015' }
```

Then `PaintViz.mount('#el', { palette: yourPalette })`.

Each swatch shows its **LRV** (Light Reflectance Value), the number painters
actually quote — computed from the hex, not hand-entered.

## Notes

- **Nothing is uploaded.** A visitor's photo is read with `FileReader` and stays in
  their browser. The only network request the widget makes is for your own scene
  files, plus the lead submission the visitor explicitly sends.
- **Selections live in the URL** (`#pv=exterior&c=siding:3a3f42:satin,…`), so
  *Copy Link* reproduces an exact combination — which is what people send you.
- **Performance**: a repaint is 2–8 ms at 1600 px because the irradiance field is
  precomputed once per surface; after that, changing color is a multiply. Only
  pixels under a mask are ever touched.
- **Accuracy disclaimer**: the widget shows one by default. Keep it. Screens vary,
  and no simulation replaces a physical sample on the actual wall.
- Browser support: any browser with `<canvas>` and `ImageData` — Chrome, Safari,
  Firefox, Edge, iOS and Android. No WebGL required.
